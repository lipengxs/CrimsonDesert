Combat Research: What Is Confirmed vs. What Needs Testing

Skills and Equipment Choices

The official site describes combat as a player-led combination of skills and equipment rather than a single prescribed answer. That supports a useful guide question—what changed when a player swaps one choice—but not a universal combo, stamina, or damage claim.

  • Record the platform, version, encounter, and equipment used
  • Change one skill or equipment choice per test
  • Describe the observed result without inventing hidden values
  • Link any fixed recommendation to reproducible evidence
Terrain and Route Context

Official material presents Pywel as a varied open world, from plains and forests to deserts and mountains. Route guides should use those confirmed landscape categories to help readers label an objective, return point, and spoiler boundary; they should not claim undocumented map bonuses, ambush rules, or exact shortcuts.

  • State whether a note is from official media or live testing
  • Use landmark descriptions before publishing coordinates
  • Keep story-sensitive route notes behind a spoiler label
  • Refresh a route when an update changes its context
No Fixed Counter Tables Without Evidence

This site does not publish fixed enemy, element, weapon, or boss-counter tables unless they are supported by a current official source or a clearly documented reproducible test. A generic rock-paper-scissors list is not a reliable Crimson Desert guide.

  • List the source and the reviewed game version
  • Separate player observation from official confirmation
  • Include the encounter scope and test conditions
  • Remove the claim when it cannot be rechecked

How to Build a Useful Post-Launch Guide

Document a Repeatable Test

A practical combat article should identify the platform, patch, equipment, encounter context, and one decision being tested. This is more valuable than a generic “master combos” paragraph.

  • One question per test
  • Visible setup and scope
  • Observed outcome and limitation
  • Source or capture date

Plan a Spoiler-Aware Route

Route pages should say whether they cover official media, a first visit, a completed-story return, or a specific collection task. That gives readers a decision point without promising hidden loot or undocumented access rules.

  • Reader goal and spoiler level
  • Starting point and return condition
  • Official or tested evidence type
  • Last-reviewed version

Keep Store and Gameplay Questions Separate

Edition contents, platform availability, performance checks, and gameplay guidance change at different speeds. Separate them so a store update does not silently invalidate a route or combat recommendation.

  • Use official storefronts for purchase decisions
  • Use patch notes for version changes
  • Label community observations clearly
  • Archive replaced advice instead of overwriting it
